# Как устроен проект (для разработки)

Сайт «Фруктовый Дом · документы» — одна страница (HTML+CSS+JS без фреймворков). Данные — в Google Таблице «Документы ФД» через Google Apps Script (`Code.gs`).

## Где что
- `dev/src/app.html` — основной код (разметка, стили, логика). Плейсхолдеры `/*__DOC_CSS__*/ /*__SEED__*/ /*__FMT__*/ /*__DOCS__*/` подставляются при сборке.
- `dev/src/docs_seg.js` — печатные формы: счёт, ТОРГ‑12, УПД (`docInvoice`, `docTorg12`, `docUPD`, `layout` — раскладка по листам).
- `dev/src/doc_css.css` — стили печатных форм. `fmt_seg.js` — форматирование (суммы прописью и т.п.). `seed_seg.js` — начальные данные и `newDraft`, `migrate`.
- `dev/Code.template.gs` — серверный скрипт таблицы (файл Code.gs в Apps Script). Паролей в нём нет: они в отдельном файле «Пароли.gs» в Apps Script (шаблон `dev/Passwords.template.gs`). Code.gs владелец заменяет целиком, «Пароли.gs» не трогает.
- Полная инструкция для ИИ-агентов — `AGENTS.md` в корне.
- Корень репозитория: `app.js` (собранная страница, её грузит Тильда frudom.ru/1c и PWA), `index.html`, `manifest.webmanifest`, `sw.js`, иконки.

## Сборка и выкладка
```
cd dev && python3 build.py && node --check out/b.js
cd tools && npm i && node min.js ../out/tilda-block.html ../out/min.html && node repo.js ../out/min.html
cd ../.. && git add -A && git commit -m "…" && git push
```

## Проверка
```
node dev/test/server.js &      # mock: настоящий Code.gs в Node vm, тестовые пароли 1111/2222/3333/4444
python3 dev/test/smoke.py      # открывает все вкладки на ПК и телефоне, считает ошибки
```
Для PDF в тестах CDN (cdnjs) нужно подменять локальными html2canvas/jspdf/xlsx (`npm pack html2canvas@1.4.1 jspdf@2.5.1 xlsx@0.18.5`).

## Важные правила
- Правки — точечные (замена кусков), не переписывать файл целиком.
- Роли: admin (Даниил) видит «Прибыль», «События», «Задачи»; manager (Наталья) — остальное; staff (Гриша, Склад) — только создание документов по ценам прайса и изменение количества; ограничения staff дублируются на сервере (`staffOk_`).
- Новые поля в карточках сохраняются в таблицу, только если добавлены в `S` в Code.gs (колонки) — после этого владелец вставляет Code.gs и разворачивает «Новую версию».
- Подписи и печати хранятся только в таблице (не в репозитории!). Staff их не получает.
- Нумерация документов — отдельная по паре «поставщик + заказчик» (`nextNum`), старт задаётся в карточке заказчика (`nums`).
