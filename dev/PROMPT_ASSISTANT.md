## 2. Что это за сайт

«Фруктовый Дом · документы» — моя замена 1С. Создаёт **счёт, ТОРГ‑12, УПД** (и XML УПД для ЭДО), ведёт журнал документов, календарь доставок, задачи на день для водителя, прибыль.

- Открывается на **frudom.ru/1c** (Тильда, блок HTML грузит файл `app.js`) и как приложение на телефоне: **dskoby-maker.github.io/frudom-docs**.
- Код лежит на **GitHub: `dskoby-maker/frudom-docs`**.
- Данные хранятся в **Google Таблице «Документы ФД»**. Сайт общается с ней через **Google Apps Script (`Code.gs`)**, развёрнутый как веб-приложение.
- Фото к задачам и файл «Мой прайс» лежат на **Google Диске** владельца. Скрипту нужен доступ к Диску: в Apps Script выбрать функцию `authorize` → «Выполнить» → «Разрешить».

### Пользователи и роли
| Пользователь | Роль | Что может |
|---|---|---|
| Даниил | admin | всё, плюс вкладки «Прибыль», «События», «Задачи» |
| Наталья | manager | всё, кроме этих трёх вкладок |

Ограничения staff продублированы на сервере (`staffOk_` в Code.gs). Пароли хранятся **только** в Apps Script у меня, в репозитории вместо них `ПАРОЛЬ`.

### Вкладки и функции (что уже сделано)
- **Новый документ.** Поставщик, заказчик, ОП, договор, номер, дата, адрес доставки. Товар ищется по мере ввода названия: в подсказках сначала прайс заказчика, потом остальные; есть «+ Создать новый товар» (сохраняется в справочник с ценой и единицей). Enter в количестве открывает новую строку. Кнопки Счёт / ТОРГ‑12 / УПД (сохраняют в журнал и показывают печатную форму), «Скачать счёт + ТОРГ‑12 одним PDF», «Сохранить в журнал без печати», «С печатью и подписью».
- **Заказ из файла** (Excel по шаблону, см. раздел 6). Если в файле несколько накладных (разные адреса или колонка «ОП»), на странице появляется блок на каждую накладную, уже заполненный, со своими кнопками, плюс «Сохранить все в журнал».
- **Заявка** (для МГУ и других заказчиков с многими точками). Таблица «точки × товары», на каждую точку своя накладная. Кнопки «Создать документы и скачать PDF» и «Сохранить в журнал без PDF».
- **Календарь.** На дне показано число точек (по накладным и задачам). Список документов дня, «Маршрут для водителя»: у точки видно 3 товара, остальные под «Раскрыть весь список»; есть текст для MAX и «Загрузить всего».
- **Задачи на день.** Видны всем. Сверху точка и блок «Прочитал: … / Не прочитал: …», ниже текст, фото, автор. Многострочный текст (Shift+Enter), фото с просмотром (приближение, поворот, листание). Карандаш открывает правку: текст, фото, дата (перенос), заказчик, точка. Черновик не теряется при сворачивании браузера. **Автозадачи**: из каждой накладной сама создаётся задача «Отвезти товар на {заказчик}, общий вес {кг}» (одна на точку и дату, пересчитывается при правке накладной, удаляется при архивации).
- **Журнал.** Фильтры, комплекты (накладные одной заявки), архив. «Счёт+ТОРГ» и «Счета+ТОРГ» у комплекта сначала открывают просмотр (счёт на книжном листе, ТОРГ‑12 на альбомном), там «Печать» и «Скачать PDF». Колонка **«Распечатан со склада»**: время, когда пользователь Склад нажал именно «Печать».
- **Заказчики и цены.** Реквизиты, тип счёта (банк / казначейство), обособленные подразделения (ОП: свой КПП, адрес, счёт). У НМИЦ гематологии ОП — это источники финансирования «Бюджет / ОМС / Внебюджет» на одном адресе, точка одна. Контакты точек для водителя, контракты (цена, срок, ИКЗ, остаток), нумерация по паре «поставщик + заказчик», цены заказчика, СТЕ/СПГЗ для Портала поставщиков.
  - **НДС в документах:** «Без НДС» (по умолчанию), «10%/22% сверху цены прайса», «10%/22% уже в цене». НДС только для частных заказчиков, **госконтракты всегда без НДС**.
  - **Цены: «Из моего прайса».** Цены берутся из файла «Прайс лист Фруктовый Дом.xlsx» на Google Диске (колонка A — название, B — цена «по безналу», первый лист) и обновляются сами при его изменении. Цены подвязанного заказчика полностью заменяются прайсом.
- **Товары, Поставщики** (реквизиты, печать и подпись, ID ЭДО), **Данные, Прибыль, События, Задачи** (мои личные).
- Работа **без связи**: всё сохраняется на устройстве, неотправленные правки переживают перезагрузку и уходят в таблицу, когда связь появится. Документ, который есть на устройстве, но не дошёл до таблицы, отправляется заново. Ошибки связи показывают настоящую причину.

## 3. Как устроен код (для правок)

```
dev/src/app.html      — основной код: разметка + стили + логика (один большой файл, без фреймворков)
dev/src/docs_seg.js   — печатные формы: docInvoice, docTorg12, docUPD, layout (раскладка ТОРГ/УПД по листам)
dev/src/doc_css.css   — стили печатных форм
dev/src/fmt_seg.js    — суммы прописью и форматирование
dev/src/seed_seg.js   — начальные данные, newDraft, migrate
dev/Code.template.gs  — серверный скрипт Google Таблицы (Code.gs, паролей в нём нет)
dev/Passwords.template.gs — шаблон файла «Пароли.gs» в Apps Script
dev/build.py          — сборка → dev/out/ (b.js для проверки, tilda-block.html, test.html)
dev/tools/min.js, repo.js — сжатие и выкладка в корень: app.js, index.html (app.js?v=<хеш>), sw.js
dev/test/server.js    — тестовый сервер: настоящий Code.gs в Node vm, пароли 1111/2222/3333/4444
dev/test/smoke.py     — открывает все вкладки на ПК и телефоне (Playwright), считает ошибки
```

Ключевые места в `app.html`: `calc()` (расчёт строк, НДС), `commitDoc()` (сохранение документа), `flush()/buildChanges()` (отправка правок в таблицу), `pull()/applyServer()` (загрузка), `renderDoc/renderLines` (форма документа), `ps*` (поиск товара), `renderCalendar/drawDayTasks/dtRow/dtEdRow` (календарь и задачи), `docTasks()` (автозадачи), `dvPoints/renderDriver` (маршрут), `renderJournal/jRowHtml/onJClick` (журнал), `showPreview/showPreviewSet` (просмотр и печать), `cardEditor/renderCustomers` (карточки), `pl*` (мой прайс), `imp*`/`mul*` (заказ из файла), `phAdd` (фото), `START_TAB` (стартовая вкладка).

Листы таблицы задаёт объект `S` в Code.gs: Поставщики, Заказчики, Товары, Цены, СТЕ, Контракты, Журнал, События, Задачи на день, Фото задач, Настройки пользователей, Закупочные цены, Себестоимость накладных, Налоги для прибыли.

## 4. Правила работы с кодом

1. **Правки точечные:** заменяй куски, не переписывай файлы целиком.
2. **Новое поле в карточке** сохранится в таблицу, только если добавить колонку в `S` в Code.gs. После этого я должен вставить новый Code.gs и сделать «Новую версию».
3. **Code.gs мне отдавай готовым файлом целиком.** Паролей в нём нет: они в отдельном файле «Пароли.gs» в Apps Script (шаблон `dev/Passwords.template.gs`), его не трогаем. Инструкция для меня: «Таблица → Расширения → Apps Script → файл Code.gs → выделить всё → вставить новый → Сохранить → Развернуть → Управление развёртываниями → карандаш → Новая версия». Если нужны новые разрешения Google, сначала выполнить `authorize`.
4. Если сайт меняется так, что ему нужен новый Code.gs, делай его **совместимым со старым скриптом** (старый скрипт не должен ломать сайт).
5. **Печати и подписи только в таблице**, не в репозитории. Staff их не получает.
6. Нумерация документов своя у каждой пары «поставщик + заказчик» (`nextNum`), старт задаётся в карточке заказчика.
7. **Проверка перед выкладкой:**
   ```
   cd dev && python3 build.py && node --check out/b.js
   node test/server.js &          # тестовый сервер на :8787
   python3 test/smoke.py          # должно быть «ошибок: 0» на ПК и телефоне
   ```
   Для тестов с Excel/PDF библиотеки с cdnjs подменяй локальными (`npm pack xlsx@0.18.5 html2canvas@1.4.1 jspdf@2.5.1`). Проверяй и на ширине телефона 360–412 px: страница не должна быть шире экрана.
   **Не останавливай тестовый сервер командой `pkill -f` с тем же текстом в команде:** она убивает саму себя.
8. **Выкладка:**
   ```
   cd dev/tools && npm i && node min.js ../out/tilda-block.html ../out/min.html && node repo.js ../out/min.html
   cd ../.. && git add -A && git commit -m "…" && git push
   ```
   После push GitHub Pages обновляется за 1–2 минуты. Мне сказать: «обновите страницу, на телефоне закройте и откройте приложение».

**Если у тебя нет доступа к GitHub и запуску кода:** попроси меня прислать ZIP репозитория (GitHub → Code → Download ZIP) или нужные файлы. Верни мне **готовые файлы целиком** и пошаговую инструкцию, как загрузить их на GitHub через сайт (открыть файл → карандаш → вставить → Commit changes). Для `app.js` нужна сборка (`build.py`, `min.js`, `repo.js`); если не можешь её запустить, прямо скажи об этом.

## 6. Заявки заказчиков → файл заказа для сайта

Я присылаю заявку в любом виде (PDF, скан, Word, Excel, фото). Ты делаешь `.xlsx` строго по шаблону, я загружаю его: «Новый документ → Загрузить файл заказа».

**Лист «Заказ».** Строка 1: `Заказ для сайта «Фруктовый Дом · документы»`, строка 2 пустая. Дальше пары «ключ | значение» в колонках A и B:
`Заказчик`, `ИНН заказчика` (только цифры, главный признак), `Договор` (с номером: «Договор № … от ДД.ММ.ГГГГ» или «Контракт № …»), `Поставщик`, `ИНН поставщика`, `Дата поставки` (ДД.ММ.ГГГГ), `Номер документа` (обычно пусто), `Адрес доставки`.

Пустая строка, затем строка заголовков:
`№ док. | Адрес доставки | ОП | Товар | Кол-во | Ед. | Цена, ₽ | Примечание | В заявке`

- **Товар** называй точно как в спецификации или прайсе заказчика на сайте.
- **Кол-во** пиши в единицах договора (обычно кг). Если в заявке указаны упаковки («2 кор», «3 пуч»), а цена за кг: «Кол-во» оставь пустым и залей жёлтым, в «В заявке» напиши как в заявке. Сайт сам подставит вес по прошлым данным. Не выдумывай веса.
- «№ док.» и «Адрес доставки» заполняй в строках, только если точек несколько. Колонка **«ОП»** нужна, чтобы разделить заявку на накладные по подразделениям (у НМИЦ: Бюджет / ОМС / Внебюджет по колонкам заявки).
- Если товара нет в спецификации, всё равно впиши строку с примечанием «нет в спецификации договора» и скажи мне.
- Если цена в заявке отличается от договора, ставь цену договора и сообщи о расхождении.
- Оформление: заголовок жирный белым на фоне #6A2C4E, тонкие рамки, закреплённая строка заголовков. Имя файла: «Заказ <короткое имя заказчика> на ДД.ММ.ГГГГ.xlsx».
- В ответе напиши: сколько позиций, сумма, что проверить вручную.
