# XML для ЕИС

В форме УПД и журнале кнопка «XML для ЕИС» формирует транспортный XML: титул продавца ФНС 5.03 и приложение ЕИС 1.23 в Windows-1251/base64, с новым идентификатором и хэшем ГОСТ Р 34.11-2012 (256). Чужая электронная подпись не переносится. Диадок остаётся отдельной выгрузкой.

Пользователь скачивает **один файл `DP_PAKET_….xml`**. Его не нужно распаковывать: оба документа находятся внутри в `Документ/Контент` и `Прилож/Контент`. Перед скачиванием проверяются обратное декодирование, совпадение идентификаторов/хэша, календарная дата и суммы строк/итогов. Это проверки согласованности, не полная XSD-валидация ЕИС.

Исправлена сборка `СведТов/СведТРУ`: создаётся отдельный контейнер для каждой строки текущей накладной, старые контейнеры образца полностью удаляются. Ранее при изменении состава товаров могли оставаться чужие строки образца.

Настройка также читает один транспортный XML и `EDOInfo.xml`. Последний содержит участников ЭДО и ссылки на полные сведения контракта; он **не считается готовой настройкой** и не заменяет существующее сопоставление. Интерфейс показывает ссылку на полный XML контракта только на HTTPS-домене zakupki.gov.ru с ожидаемым путём. Полная спецификация `contract` импортируется из XML или TXT, скопированного из просмотра XML в браузере. После образца УПД загрузите полный контракт: все позиции появятся в настройке с порядковым номером, точной ценой, кодом и единицей. Версия контракта, стороны, этап, адрес и идентификаторы известных строк сверяются с образцом. Идентификаторы новых строк берутся из `guid`, `sid`, `externalSid`; не вычисляются из названий. Поддерживаются обычные недетализированные товары без НДС, кг/шт, без специальных реестровых номеров. Полный исходный XML и подписи не сохраняются: только компактная спецификация в закрытой ячейке `contracts.eis`.

## Проверенные источники и ограничения (28.10.2026)

- Руководство ЕИС для поставщика, версия 12.1, разделы 4.1.3 и 4.1.5: [официальный документ на зеркале](https://ppt.ru/fls/125482/rukovodstvo-polzovatelya-po-elektronnomu-aktirovaniyu-dlya-postavshchika-2022-08.pdf). Описывает выгрузку EDOInfo со ссылкой на `contract` и загрузку одного XML. Это архивное руководство, а не подтверждение актуальности схем 2026 года.
- [Описание обработки транспортного пакета на региональном портале закупок](https://zakupki.admhmao.ru/images/2022.28_44.pdf): base64 → Windows-1251 для УПД и приложения.
- [Официальный раздел форматов ЕИС](https://zakupki.gov.ru/epz/main/public/document/view.html?sectionId=432). Актуальный комплект XSD получить в этой среде не удалось. Запрос полного контракта по ссылке из пользовательского EDOInfo вернул HTTP 503.

Внешние источники не подтверждают принятие именно нашего файла: для этого требуется реальный импорт в личном кабинете ЕИС. Исправления/корректировочные документы и другой адрес нельзя объявлять поддержанными по одному HTML-представлению. Присланный полный contract разобран отдельно: 61 позиция проверена вместе с исходным ZIP, включая выгрузку всех строк и произвольного поднабора.

Сначала требуется установить актуальный `Code.gs` и развернуть новую версию Apps Script по прежнему адресу. В лист «Контракты» добавляется служебная колонка `eis`. Образцы и сопоставления хранятся в закрытой таблице, не в публичном исходном коде.

В УПД выбрать контракт, нажать «Настроить ЕИС», загрузить ZIP ЕИС (или основной XML и PRIL), сопоставить товары, проверить страны происхождения, подтвердить адрес и этап. Затем сохранить и нажать «XML для ЕИС». При смене адреса/этапа загрузить соответствующий образец. Для товаров вне образца дополнительно загрузить полный XML контракта и один раз сопоставить позиции. Один шаблон по-прежнему привязан к одному адресу/этапу; импорт каталога не меняет адрес поставки.

Поддерживаются обычные товары (`НедеталТРУ` / `НеЛПСвед`) и один адрес поставки. Корректировки, лекарства, работы с детализацией и документы с дополнительными вложениями требуют отдельной реализации. Количество — до трёх знаков после запятой. НДС берётся из рассчитанной накладной. Страна из карточки товара приоритетнее подтверждённой страны из настройки ЕИС. Цена контракта в приложении сохраняется из образца.

После загрузки XML в личном кабинете ЕИС проверить проект, реквизиты, суммы и подписанта, затем подписать собственной электронной подписью. Автоматическая проверка по действующему полному комплекту XSD и фактический приём в личном кабинете ЕИС не выполнены. Локальные тесты проверяют структуру пакета, связь двух XML, точные байты/контрольную сумму оригинального образца и ошибки сопоставления.

## Проверено загрузкой в ЕИС (29.10.2026)

Файл `DP_PAKET_….xml` загружен в личном кабинете поставщика («Загрузка документа из файла» → «Документ о приемке/счет-фактура»). Найденные требования схемы:

- в приложении `ФайлУПДПрод` обязателен блок `Подписант` (ошибка РДИК_ИК_1079);
- `Подписант` — **пустой** элемент с атрибутами `ПорядНом` (порядковый номер подписанта, `1`) и `ЛогинПрод` (логин пользователя ЕИС поставщика). Вложенные элементы (ФИО) не допускаются;
- блок стоит последним в `ФайлУПДПрод`.

Логин берётся из карточки поставщика (поле «Логин ЕИС подписанта», колонка в листе «Поставщики»).
После этого схемная проверка проходит; дальше ЕИС проверяет только содержание: уникальность номера+даты (РДИК_0063), дату не раньше текущей (РДИК_0595 — сайт проверяет заранее), отсутствие на этапе документов «Отказано при рассмотрении» без исправления (РДИК_0359).

## Адреса поставки из контракта (29.10.2026)

В «Настроить ЕИС» можно загрузить XML контракта (`cpElectronicContract`, со страницы закупки) — из него берутся все места поставки (код ГАР и адрес). Номера мест в реестре ЕИС (`ИдМестаПоставкиКонт`, 605200xx) отличаются от номеров в этом XML (439xxxxx), но порядок мест одинаковый: место с индексом i в XML = `catalog.places[i]` из реестрового контракта. Сопоставление проверяется по образцу (место образца должно совпасть по коду ГАР). Проверено загрузкой в ЕИС: документ на Орджоникидзе, 15 получил верный адрес.

При выгрузке адрес накладной сравнивается с адресами контракта по словам улицы, номеру дома, строения и корпуса. В приложении подставляются `ИдМестаПоставкиКонт`, `СтрокаГАР`, `АдрГАР/@ИдНом`, `ЗемелУчасток` (улица); `Индекс` удаляется, если адрес отличается от образца. Если реестровый XML контракта сам содержит адреса, они берутся из него напрямую.
