# CLAUDE.md — правила работы (экономия лимитов без потери качества)

## Кто я и как со мной говорить
- Даниил, владелец Frudom (сухофрукты, Ozon, опт). Программировать не умею.
- Отвечай по-русски, просто, по шагам, без жаргона.
- Коротко: сначала ответ/результат, потом 1–3 строки пояснения. Без вступлений, без пересказа того, что сделал по шагам.
- В репозитории frudom-docs: после успешных проверок сам мерджи PR, не проси меня жать Merge.

## 1. Выбор модели под задачу
Перед задачей оцени сложность и выбери самую дешёвую модель, которая точно справится.

| Сложность | Модель | Примеры |
|---|---|---|
| Простая | **haiku** | найти файл/строку, переименовать, поправить опечатку, переформатировать таблицу, перевести текст, вытащить данные из документа, короткий ответ на вопрос |
| Средняя | **sonnet** | обычные правки кода, новая небольшая функция, разбор Excel/PDF заказа, письма, тексты карточек Ozon, расчёт юнит-экономики по готовой формуле |
| Сложная | **opus** | архитектура, баг, который не находится за 2 попытки, изменения в нескольких связанных файлах, расчёт госконтрактов (с подводными камнями), юридические/налоговые схемы, всё, где ошибка дорого стоит |

Правила:
- Начинай с дешёвой модели. Если она дважды ошиблась или «плавает» — поднимай на уровень выше, не мучай дальше.
- Не используй opus для механической работы, даже если она длинная.
- Деньги, налоги, договоры, госконтракты — минимум sonnet, проверка итоговых цифр обязательна.

## 2. Когда звать субагента (и когда НЕТ)
Субагент стартует «с нуля» и сам тратит токены. Поэтому:

**Звать, когда:**
- нужно перерыть много файлов/страниц, а мне нужен только вывод (поиск по проекту, сравнение 10+ документов, сбор данных из многих источников);
- можно распараллелить независимые части (3 отдельных поставщика, 3 отдельных отчёта);
- нужна независимая проверка важного результата (расчёт контракта, итоговые суммы).

**Не звать, когда:**
- задача на 1–3 шага — делай сам;
- нужен контекст, который уже есть в текущем разговоре;
- ради «подстраховки».

**Как звать:**
- Субагенту для поиска/чтения — **haiku**; для анализа — **sonnet**; opus только для сложной проверки.
- Давай короткое, точное задание: что найти, где, в каком виде вернуть (список, 5 строк, таблица). Проси вернуть только вывод, без пересказа файлов.

## 3. Экономия на чтении
- Не читай файл целиком, если нужна часть: сначала поиск (Grep/Glob), потом чтение нужного куска (offset/limit).
- Не перечитывай файл, который только что сам изменил.
- Большие таблицы/выгрузки не листай в чате — обрабатывай скриптом и выдавай итог.
- Не открывай файлы «на всякий случай». Только то, что нужно для ответа.

## 4. Экономия на ответах и действиях
- Правишь файл — используй точечную правку (Edit), не переписывай файл целиком.
- Попросили изменить одно — меняй одно, не выдавай весь текст/код заново.
- Не повторяй в ответе то, что я уже вижу (содержимое файла, ссылку, шаги).
- Похожие действия делай пачкой за один заход (несколько поисков сразу, несколько правок подряд), а не по одному с комментариями.
- Не пиши план и не жди одобрения для понятных задач — сразу делай.
- Уточняющий вопрос — только если ошибка будет дорогой. Один вопрос, не пять.

## 5. Поиск в интернете
- Знаешь ответ и он не меняется со временем — отвечай без поиска.
- Цены, законы, налоги, ставки, правила Ozon — ищи (они меняются).
- Обычный поиск по умолчанию; «глубокий» — только если обычный ничего не дал.

## 6. Длинные сессии
- Когда задача закончена и начинается новая, не связанная — лучше новый чат (/clear), чтобы не тащить старый контекст.
- Если разговор очень длинный — сожми его (/compact) и продолжай.
- Важное, что пригодится потом, записывай в этот файл коротко, а не держи в разговоре.

## 7. Чего НЕ экономить
- Проверку денег, сумм, НДС/налогов, реквизитов в документах (счёт, ТОРГ-12, УПД).
- Подводные камни при расчёте госконтрактов — расписывать подробно всегда.
- Проверку, что код/файл реально работает, перед тем как сказать «готово».
