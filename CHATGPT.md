## Перед любой задачей
1. Возьми свежую ветку `main` и прочитай в корне проекта **AGENTS.md** (что уже есть на сайте, где что в коде, роли, заказчики, правила) и **.cursor/rules/frudom.mdc** (порядок работы). Это главный источник правды — верь им больше, чем своей памяти.
2. Работай в отдельной ветке.

## Кто заказчик и как с ним говорить
- Даниил, владелец бизнеса, живёт в Испании, **программировать не умеет**.
- Только по-русски, просто, без технических слов. Не проси его править код, запускать команды или «вставить строчку» — всё делаешь сам.
- Ответ короткий: что изменилось **на экране** (по пунктам) → что сделать ему (по шагам, только если нужно) → на что обратить внимание. Без вступлений и пересказа работы.
- Он присылает скриншоты с телефона — смотри внимательно: что криво, перекрыто, не помещается. Телефон — главный экран (ширина 360–412 px).
- «Сделай как положено», «логику ты понял» = продумай сценарий сам, с крайними случаями. Вопрос — только если ошибка дорогая (деньги, номера документов, госконтракты, удаление данных), и один.

## Как думать
- Пойми настоящую цель, а не только слова («в прибыли не все заказчики» = показать всех и чтобы новые появлялись сами).
- Найди место в коде поиском по тексту с экрана. Сначала ищи, нет ли уже похожего, и переиспользуй (`openCard`, `docCard`, `bundleCard`, `toast`, `opts`, `cusNm`, `tabBackFrom`, `fm`, `fd`, `r2`, `esc`, `MONEY_SEL`…).
- Продумай: пусто / один / много; Гриша (водитель, ограничен) и Склад; телефон; без связи; старый скрипт таблицы; архив; данные с другого устройства.
- Сайт должен сам догадываться и подставлять, но всегда давать поправить руками и отменить.
- Правки точечные, не переписывай файлы целиком, не трогай то, о чём не просили.

## Правила интерфейса (обязательно)
- Любое число/плитка/счётчик нажимается → подробности → можно глубже → всегда путь «‹ Назад» (`CARD_RE` + `openCard`, `tabBackFrom`).
- Заказчики — короткие названия (`cusNm`, списки через `opts`); в сами документы — только полные.
- Деньги в полях — с пробелами по тысячам (`MONEY_SEL`, `type="text" inputmode="decimal"`).
- Без эмодзи — линейные SVG-иконки. Цвета по смыслу: зелёный — готово, жёлтый — внимание, красный — ошибка/просрочено, сливовый — основное.
- Ничего не вылезает вбок на телефоне; счётчики не наезжают на слова; без системного `datalist`.
- Короткие плавные анимации; подсказки «?» к новому; уведомления — `toast`, у удаления — «Отменить».

## Опасные места
- Новое хранимое поле = колонка в конце списка `S` в `dev/Code.template.gs`. Если без нового скрипта не сохранится — подними `CODE_VER` и `NEED_VER` на 1 и закрой функцию до обновления скрипта (с подсказкой). Сайт обязан работать со старым скриптом.
- Не трогать без прямой просьбы: нумерацию документов, суммы/НДС/округление (`r2`), печатные формы, `API_URL`. Госконтракты — всегда без НДС.
- Никогда не класть в репозиторий пароли, ключи, печати, реквизиты и данные заказчиков — репозиторий открыт.

## Порядок работы
1. Правки в `dev/src/*` (и `dev/Code.template.gs`, если нужно).
2. `cd dev && python3 build.py && node --check out/b.js`
3. `node test/server.js &` (тестовый сервер, пароли 1111/2222/3333/4444 = Даниил/Наталья/Гриша/Склад), `python3 test/smoke.py` — обе строки «ошибок: 0».
4. На каждую новую функцию — свой тест `dev/test/<имя>.py` (Playwright, по образцу соседних): действие + проверка на странице и в данных (`curl localhost:8787/dump`), ширина 1300 и 390, «нет прокрутки вбок», «нет ошибок JS». Прогони тесты соседних функций. Посмотри на снимки экрана глазами.
5. Выкладка: `cd dev/tools && npm ci && node min.js ../out/tilda-block.html ../out/min.html && node repo.js ../out/min.html` (без сети — сжать через esbuild и `node repo.js`).
6. Коротко записать изменение в AGENTS.md (в нужный пункт раздела 2: **название**, дата, имена функций, что видит пользователь, где хранятся данные, имя теста).
7. Коммит: `dev/src/*`, Code.gs (если менялся), тест, `app.js`, `index.html`, AGENTS.md. `dev/out/` не коммитить. Конфликт в `app.js`/`index.html` при обновлении ветки — не править руками, а пересобрать.
8. PR на русском: «Что сделано» (как выглядит на сайте) / «Как проверено» / «Что сделать Даниилу» (если менялся Code.gs — шаги: открыть `dev/Code.template.gs` → «Copy raw file» → Apps Script → Code.gs → выделить всё → вставить → «Сохранить» → «Развернуть» → «Управление развёртываниями» → карандаш → «Новая версия» → «Развернуть»; файл «Пароли.gs» не трогать) / «На что обратить внимание».
9. Если можешь — сам слей PR после проверок. Если не можешь — напиши Даниилу: «Нажмите зелёную кнопку Merge pull request → Confirm merge».
