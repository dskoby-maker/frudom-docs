## 2. Что это за сайт

«Фруктовый Дом · документы» — моя замена 1С. Создаёт **счёт, ТОРГ‑12, УПД** (и XML УПД для ЭДО), ведёт журнал документов, календарь доставок, задачи на день для водителя, прибыль.

- Открывается на **frudom.ru/1c** (Тильда, блок HTML грузит файл `app.js`) и как приложение на телефоне: **dskoby-maker.github.io/frudom-docs**.
- Код лежит на **GitHub: `dskoby-maker/frudom-docs`**.
- Данные хранятся в **Google Таблице «Документы ФД»**. Сайт общается с ней через **Google Apps Script (`Code.gs`)**, развёрнутый как веб-приложение.
- Фото к задачам и файл «Мой прайс» лежат на **Google Диске** владельца. Скрипту нужен доступ к Диску: в Apps Script выбрать функцию `authorize` → «Выполнить» → «Разрешить».

### Вкладки и функции (что уже сделано)
- **Новый документ.** Поставщик, заказчик, ОП, договор, номер, дата, адрес доставки. Товар ищется по мере ввода названия: в подсказках сначала прайс заказчика, потом остальные; есть «+ Создать новый товар» (сохраняется в справочник с ценой и единицей). Enter в количестве открывает новую строку. Повтор одной позиции в документе (`dupLines`/`dupWarn`): обе строки красные с подписью «уже есть в строке № …» и всплывающее предупреждение; сохранять не мешает. Тест: `dev/test/dup-lines.py`. Кнопки Счёт / ТОРГ‑12 / УПД (сохраняют в журнал и показывают печатную форму), «Скачать счёт + ТОРГ‑12 одним PDF», «Сохранить в журнал без печати», «С печатью и подписью».
- **Заказ из файла**: заявка как есть — PDF с текстом (pdf.js), Word .docx (JSZip), Excel любого вида, .txt или «Вставить текст» (`ft*` в app.html: `ftRead` → `ftParse` → `impResolve`). Заказчик — по номеру договора → ИНН → названию; дата — рядом со словом «поставка»/«на»; таблица по заголовку «Наименование … Количество» (`ftTable`, колонки ОП «Бюджет/ОМС/Внебюджет» → отдельные накладные), иначе по строкам «товар N кг» (`ftLines`). Сомнительное — жёлтые замечания, ненайденное — красное. Сканы/фото — по кнопке «Прочитать через ИИ»: сайт → действие `aiRead` в Code.gs (без блокировки) → Gemini (`gemini-flash-latest`, запасная `gemini-3.8-flash`, свойство `GEMINI_MODEL`) → JSON → `aiSrc` → тот же `ftParse`. Ключ — свойство скрипта `GEMINI_KEY`, админ вставляет его на сайте (действие `aiKey`), в репозитории ключа нет. Сайт пишет, чем прочитана заявка («без ИИ» / «прочитан ИИ»). Шаблон Excel (раздел 6) работает по-старому. Если в файле несколько накладных (разные адреса или колонка «ОП»), на странице появляется блок на каждую накладную, уже заполненный, со своими кнопками, плюс «Сохранить все в журнал».
- **Заявка** (для МГУ и других заказчиков с многими точками). Таблица «точки × товары», на каждую точку своя накладная. Кнопки «Создать документы и скачать PDF» и «Сохранить в журнал без PDF». Переключатель «Вид таблицы» (`oView`/`oSetView`): «Адреса в строках» или «Товары в строках» (адреса/ОП в столбцах, № док. в шапке столбца) — запоминается для каждого заказчика в личных настройках (`prefs.ov`); у заказчиков с ОП на одном адресе (НМИЦ) по умолчанию «товары в строках». Поля количества несут `data-a` (номер адреса) и `data-p` (товар); Enter/↑↓ — соседняя клетка столбца. Тест: `dev/test/profit-pay.py`.
- **Календарь.** На дне показано число точек (по накладным и задачам). Список документов дня, «Маршрут для водителя»: у точки видно 3 товара, остальные под «Раскрыть весь список»; точки одного заказчика (2+) — одна свёрнутая карточка в цвете заказчика («№ 1–6», «6 точек · 6 накладных · 135 кг», точки чипами, «без контактов: N»), раскрывается плавно, внутри у точки — её название без повтора заказчика (`dvGroupHtml`, открытость — `frudom-dvg` по дню; тест `dev/test/dv-groups.py`); текст для MAX не меняется; есть текст для MAX и «Загрузить всего».
- **Задачи на день.** Видны всем. Сверху точка и блок «Прочитал: … / Не прочитал: …», ниже текст, фото, автор. Многострочный текст (Shift+Enter), фото с просмотром (приближение, поворот, листание). Карандаш открывает правку: текст, фото, дата (перенос), заказчик, точка. Черновик не теряется при сворачивании браузера. **Цвет и группы** (`dtHue`, `dtGroups/dtGroupHtml/dtgToggle`): у каждого заказчика свой мягкий цвет (порядок в справочнике × «золотой угол», всегда одинаковый), без заказчика — без цвета; 2+ задачи одного заказчика — одна карточка-стопка («N задач · N точек», точки чипами, «N новые»), раскрывается плавно, внутри у задачи только точка; открытость запоминается на устройстве (`frudom-dtg`, по дню и заказчику); «Прочитал» ставится только для показанных задач (свёрнутые — при раскрытии). Тест: `dev/test/dt-groups.py`. **Автозадачи**: из каждой накладной сама создаётся задача «Отвезти товар на {заказчик}, общий вес {кг}» (одна на точку и дату, пересчитывается при правке накладной, удаляется при архивации).
- **Журнал.** Фильтры, комплекты (накладные одной заявки), архив. «Счёт+ТОРГ» и «Счета+ТОРГ» у комплекта сначала открывают просмотр (счёт на книжном листе, ТОРГ‑12 на альбомном), там «Печать» и «Скачать PDF». Колонка **«Распечатан со склада»**: время, когда пользователь Склад нажал именно «Печать».

История правок — `snap.meta.hist` [{at, by, w:[что изменилось]}], пишется в `commitDoc` (`docDiff`) и `setArch`. «Редактировать комплект» — `bundleEdit`: комплект открывается во вкладке «Заявка» (`O().edit`), сохранение обновляет те же документы, пустая строка — документ в архив.

Реквизиты, тип счёта (банк / казначейство), обособленные подразделения (ОП: свой КПП, адрес, счёт). У НМИЦ гематологии ОП — это источники финансирования «Бюджет / ОМС / Внебюджет» на одном адресе, точка одна. ## 5. Code.gs (Google Apps Script) — как Даниил его обновляет

- В Apps Script таблицы «Документы ФД» два файла: **Code.gs** (код, = `dev/Code.template.gs`) и **Пароли.gs** (пароли, = `dev/Passwords.template.gs` с настоящими паролями).
- **Никогда не добавляй пароли и блок `USERS` в `dev/Code.template.gs`** и вообще в репозиторий — он открыт всем. Новые пользователи/роли — только как инструкция Даниилу, что вписать в «Пароли.gs».
- Новое поле в карточках сохраняется в таблицу, только если добавлена колонка в `S` в Code.gs. Добавляй колонки **в конец** списка, ничего не переставляй.
- Сайт должен работать и со старым Code.gs (Даниил может вставить его позже): новые действия сервера — с понятной ошибкой на сайте, если их ещё нет.
- **Версия скрипта:** `CODE_VER` в Code.gs и `NEED_VER` в app.html. Меняешь Code.gs так, что сайт без нового скрипта что-то не сохранит, — увеличь обе на 1: у всех появится жёлтая плашка «Скрипт таблицы старый» с кнопкой «Как обновить» (`srvVerCheck`). Функцию, данные которой старый скрипт не сохранит, **не давай использовать** до обновления (как категории при `!D.catSrv`) — иначе работа пропадёт при следующей загрузке. Тест: `dev/test/cats-oldsrv.py`.
- Шаги для Даниила (вставляй в PR, если Code.gs менялся):
  1. Открыть в GitHub файл `dev/Code.template.gs` → кнопка «Copy raw file» (значок двух квадратиков).
  2. Таблица «Документы ФД» → «Расширения» → «Apps Script» → файл **Code.gs** → выделить всё (Ctrl+A) → вставить (Ctrl+V) → «Сохранить». Файл «Пароли.gs» **не трогать**.
  3. «Развернуть» → «Управление развёртываниями» → карандаш → «Новая версия» → «Развернуть».
  4. Если код стал использовать новые сервисы Google — сначала выбрать функцию `authorize` → «Выполнить» → «Разрешить».

- Не храни в репозитории пароли, печати/подписи, данные заказчиков из таблицы, заявки и документы (репозиторий публичный).
