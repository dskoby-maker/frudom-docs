## 2. Что это за сайт

«Фруктовый Дом · документы» — моя замена 1С. Создаёт **счёт, ТОРГ‑12, УПД** (и XML УПД для ЭДО), ведёт журнал документов, календарь доставок, задачи на день для водителя, прибыль.

- Открывается на **frudom.ru/1c** (Тильда, блок HTML грузит файл `app.js`) и как приложение на телефоне: **dskoby-maker.github.io/frudom-docs**.
- Код лежит на **GitHub: `dskoby-maker/frudom-docs`**.
- Данные хранятся в **Google Таблице «Документы ФД»**. Сайт общается с ней через **Google Apps Script (`Code.gs`)**, развёрнутый как веб-приложение.
- Фото к задачам и файл «Мой прайс» лежат на **Google Диске** владельца. Скрипту нужен доступ к Диску: в Apps Script выбрать функцию `authorize` → «Выполнить» → «Разрешить».

### Вкладки и функции (что уже сделано)

Enter в количестве открывает новую строку. Повтор одной позиции в документе (`dupLines`/`dupWarn`): обе строки красные с подписью «уже есть в строке № …» и всплывающее предупреждение; сохранять не мешает. Тест: `dev/test/dup-lines.py`. **Страховка адреса от путаницы ОП** (08.11.2026, `shipSim/shipElsewhere/shipWarn` в app.html после `#d-ship`): «Другой адрес…», который совпадает или похож (`shipSim` ≥ 0,6: та же улица + те же номера дома/корпуса, разное написание «пр-т/проспект», «к1/корп. 1», индекс и «г. Москва» не важны) на адрес **другого** подразделения того же заказчика, а в своём ОП такого нет → жёлтое окошко под полем `#d-shipw` «Похожий адрес — в другом подразделении: «…»» с кнопками «Перейти в «…»» (меняет ОП и выбирает адрес из списка) и «Адрес верный, оставить» (`dr.shipOk` = ключ адреса, переносится на следующий документ); пока не решено — Счёт/ТОРГ/УПД/«Сохранить» не срабатывают (перехват на `#tab-doc`, подсвечивает окошко). То же в «Заявке» (`#o-addaddr` — вопрос) и в заказе из файла (замечание у накладной). Тест: `dev/test/ship-branch.py`. Кнопки Счёт / ТОРГ‑12 / УПД (сохраняют в журнал и показывают печатную форму), «Скачать счёт + ТОРГ‑12 одним PDF», «Сохранить в журнал без печати», «С печатью и подписью».
- **Заказ из файла**: заявка как есть — PDF с текстом (pdf.js), Word .docx (JSZip), Excel любого вида, .txt или «Вставить текст» (`ft*` в app.html: `ftRead` → `ftParse` → `impResolve`). Заказчик — по номеру договора → ИНН → названию; дата — рядом со словом «поставка»/«на»; таблица по заголовку «Наименование … Количество» (`ftTable`, колонки ОП «Бюджет/ОМС/Внебюджет» → отдельные накладные), иначе по строкам «товар N кг» (`ftLines`). Сомнительное — жёлтые замечания, ненайденное — красное. Сканы/фото — по кнопке «Прочитать через ИИ»: сайт → действие `aiRead` в Code.gs (без блокировки) → Gemini (модель и запасная — в «Данные» → «ИИ», по умолчанию `gemini-flash-latest` и `gemini-3.8-flash`) → JSON → `aiSrc` → тот же `ftParse`. ## 3а. Правило интерфейса: «провалиться и вернуться» (просьба Даниила, 08.11.2026)

Действует для всего сайта — и для нового, и при правках старого:
- **Всё, что показывает число или итог, нажимается** и открывает подробности: плитка / итог / счётчик → окно со списком того, из чего число сложилось (по заказчикам, накладным, товарам, датам), с фильтрами там, где их больше 10.
- **Из подробностей можно идти глубже**: строка накладной → `docCard`, заказчик → его окно (`pvLedger` и т. п.), товар → карточка товара / склада. У строки — стрелка › и курсор-рука.
- **Всегда есть путь назад к месту, откуда начали**: окна — через `openCard` + `CARD_RE`/`SK_RE` (в шапке «‹ Назад», Esc, «Назад» телефона), переход в другую вкладку — через `tabBackFrom(подпись, переход)` (кнопка «‹ Назад: …» сверху). Окно, из которого можно уйти глубже, обязано уметь открыться заново (задать `CARD_RE` перед `openCard`); закрыть окно и открыть другое — через `navStash(d)`, а не просто `d.close()`.
- Образец: «Прибыль» → плитки (`pfDetail` в pfv_seg.js). Тест цепочки «туда-обратно» — как в `dev/test/pf-detail.py`.

## 3б. Правило: суммы в полях ввода — с пробелами по тысячам (просьба Даниила, 08.11.2026)

- Любое поле, где вводятся **деньги** (цена, сумма, закупка, оплата, лимит, цена договора), показывает разряды пробелами прямо при вводе: «60 000», «1 250 000,50». Количество, вес, проценты, номера — без пробелов.
- Сделано одним местом: `MONEY_SEL` и `moneyGrp` в конце `dev/src/fmt_seg.js`. Пробелы только на экране — `el.value` возвращает число без пробелов (свой геттер у поля), поэтому остальной код читает поля как раньше; курсор при вводе не прыгает; поля, заполненные кодом или пришедшие в разметке, тоже форматируются (MutationObserver).
- **Новое поле денег** — добавить его селектор в `MONEY_SEL` или поставить атрибут `data-money`. Поля денег — только `type="text"` с `inputmode="decimal"` (в `type="number"` пробелы не ставятся). Тест: `dev/test/money-input.py`.
- ⚠ `dev/test/stock-multi.py` падает на «окно без прокрутки вбок» и на main (08.11.2026) — к этому не относится.

4. **Выкладка в корень** (сайт грузит `app.js` из корня репозитория):
   ```
   cd dev/tools && npm ci && node min.js ../out/tilda-block.html ../out/min.html && node repo.js ../out/min.html
   ```
   Закоммить вместе: изменённые `dev/src/*`, `dev/Code.template.gs` (если менялся) **и** пересобранные `app.js`, `index.html` в корне. Папку `dev/out/` не коммить.
5. **PR.** Описание PR на русском, по шаблону:
   - **Что сделано** — 2–5 пунктов, как это выглядит на сайте;

## 5. Code.gs (Google Apps Script) — как Даниил его обновляет

- В Apps Script таблицы «Документы ФД» два файла: **Code.gs** (код, = `dev/Code.template.gs`) и **Пароли.gs** (пароли, = `dev/Passwords.template.gs` с настоящими паролями).
- **Никогда не добавляй пароли и блок `USERS` в `dev/Code.template.gs`** и вообще в репозиторий — он открыт всем. Новые пользователи/роли — только как инструкция Даниилу, что вписать в «Пароли.gs».
- Новое поле в карточках сохраняется в таблицу, только если добавлена колонка в `S` в Code.gs. Добавляй колонки **в конец** списка, ничего не переставляй.
- Сайт должен работать и со старым Code.gs (Даниил может вставить его позже): новые действия сервера — с понятной ошибкой на сайте, если их ещё нет.
- **Версия скрипта:** `CODE_VER` в Code.gs и `NEED_VER` в app.html. Меняешь Code.gs так, что сайт без нового скрипта что-то не сохранит, — увеличь обе на 1: у всех появится жёлтая плашка «Скрипт таблицы старый» с кнопкой «Как обновить» (`srvVerCheck`). Функцию, данные которой старый скрипт не сохранит, **не давай использовать** до обновления (как категории при `!D.catSrv`) — иначе работа пропадёт при следующей загрузке. Тест: `dev/test/cats-oldsrv.py`.
- Шаги для Даниила (вставляй в PR, если Code.gs менялся):
  1. Открыть в GitHub файл `dev/Code.template.gs` → кнопка «Copy raw file» (значок двух квадратиков).
  2. Таблица «Документы ФД» → «Расширения» → «Apps Script» → файл **Code.gs** → выделить всё (Ctrl+A) → вставить (Ctrl+V) → «Сохранить». Файл «Пароли.gs» **не трогать**.
  3. «Развернуть» → «Управление развёртываниями» → карандаш → «Новая версия» → «Развернуть».
  4. Если код стал использовать новые сервисы Google — сначала выбрать функцию `authorize` → «Выполнить» → «Разрешить».
