«Фруктовый Дом · документы» — моя замена 1С. Создаёт **счёт, ТОРГ‑12, УПД** (и XML УПД для ЭДО), ведёт журнал документов, календарь доставок, задачи на день для водителя, прибыль.

### Вкладки и функции (что уже сделано)
- **Новый документ.** Поставщик, заказчик, ОП, договор, номер, дата, адрес доставки. Товар ищется по мере ввода названия: в подсказках сначала прайс заказчика, потом остальные; есть «+ Создать новый товар» (сохраняется в справочник с ценой и единицей). Enter в количестве открывает новую строку. Кнопки Счёт / ТОРГ‑12 / УПД (сохраняют в журнал и показывают печатную форму), «Скачать счёт + ТОРГ‑12 одним PDF», «Сохранить в журнал без печати», «С печатью и подписью».
- **Заказ из файла** (Excel по шаблону, см. раздел 6). Если в файле несколько накладных (разные адреса или колонка «ОП»), на странице появляется блок на каждую накладную, уже заполненный, со своими кнопками, плюс «Сохранить все в журнал».
- **Заявка** (для МГУ и других заказчиков с многими точками). Таблица «точки × товары», на каждую точку своя накладная. Кнопки «Создать документы и скачать PDF» и «Сохранить в журнал без PDF».
- **Календарь.** На дне показано число точек (по накладным и задачам). Список документов дня, «Маршрут для водителя»: у точки видно 3 товара, остальные под «Раскрыть весь список»; есть текст для MAX и «Загрузить всего».
- **Задачи на день.** Видны всем. Сверху точка и блок «Прочитал: … / Не прочитал: …», ниже текст, фото, автор. Многострочный текст (Shift+Enter), фото с просмотром (приближение, поворот, листание). Карандаш открывает правку: текст, фото, дата (перенос), заказчик, точка. Черновик не теряется при сворачивании браузера. **Автозадачи**: из каждой накладной сама создаётся задача «Отвезти товар на {заказчик}, общий вес {кг}» (одна на точку и дату, пересчитывается при правке накладной, удаляется при архивации).
- **Журнал.** Фильтры, комплекты (накладные одной заявки), архив. «Счёт+ТОРГ» и «Счета+ТОРГ» у комплекта сначала открывают просмотр (счёт на книжном листе, ТОРГ‑12 на альбомном), там «Печать» и «Скачать PDF». Колонка **«Распечатан со склада»**: время, когда пользователь Склад нажал именно «Печать».
- **Карточки и история.** Клик по заказчику в журнале — `docCard`, по комплекту — `bundleCard` (общий `openCard`). История правок — `snap.meta.hist` [{at, by, w:[что изменилось]}], пишется в `commitDoc` (`docDiff`) и `setArch`. «Редактировать комплект» — `bundleEdit`: комплект открывается во вкладке «Заявка» (`O().edit`), сохранение обновляет те же документы, пустая строка — документ в архив.
- **Заказчики и цены.** Реквизиты, тип счёта (банк / казначейство), обособленные подразделения (ОП: свой КПП, адрес, счёт). У НМИЦ гематологии ОП — это источники финансирования «Бюджет / ОМС / Внебюджет» на одном адресе, точка одна. Контакты точек для водителя, контракты (цена, срок, ИКЗ, остаток), нумерация по паре «поставщик + заказчик», цены заказчика, СТЕ/СПГЗ для Портала поставщиков.
  - **НДС в документах:** «Без НДС» (по умолчанию), «10%/22% сверху цены прайса», «10%/22% уже в цене». НДС только для частных заказчиков, **госконтракты всегда без НДС**.
  - **Цены: «Из моего прайса».** Цены берутся из файла «Прайс лист Фруктовый Дом.xlsx» на Google Диске (колонка A — название, B — цена «по безналу», первый лист) и обновляются сами при его изменении. Цены подвязанного заказчика полностью заменяются прайсом.
- **Закупка** (только admin, `zk*` в app.html). Вставляешь сообщения закупщика Саида («Цирк / Памидор 37х110=4050 / Телега 500») → сайт находит заказчика по названию точки и его накладные на дату закупки (±3 дня, сначала тот же и следующий день), сопоставляет строки с товарами накладной (опечатки, синонимы, исключение, «Укроп Петрушка» → два товара). Сохранение пишет закупочную цену за единицу (сумма / (кол-во × вес единицы Саида)) в «Себестоимость накладных» (`lines`, служебный ключ `_zk`), телегу/машины — в прочие расходы пропорционально сумме накладных. Выученное (название → товар, коробка = N кг, точка → заказчик) — в личных настройках (`prefs.zk`). Кнопка «Скопировать для Google Таблицы» — блок в формате таблицы закупок. У точки можно выбрать любую накладную заказчика («+ Другая накладная…») или «Без накладной» (сравнение с прайсом заказчика, сохранение — в «Закупочные цены» для этого заказчика с даты закупки). Колонки «По договору» (цена из накладной без НДС, без накладной — из прайса) и «Валовая прибыль». Сводка замечаний `zkNotes`: дороже договора, низкая наценка, куплено больше/меньше накладной, ошибка в арифметике Саида, нераспознанные строки — 3 первых, остальные под «Ещё N». **История закупок**: лист «Закупки» (`purchases`, только admin; текст Саида, дата, `state` = выбор накладных и что сохранено по каждой точке). Закупка сохраняется сама (`zkStore`, через 1,5 с после правки), открывается из «Все закупки» на любом устройстве; повторное сохранение снимает закупку с накладных, которые больше не выбраны (`zkUndoDoc`, по `_zk.k` = id закупки); удаление закупки убирает её цены и телегу из прибыли. Если скрипт таблицы старый — закупки хранятся только на устройстве (`_local`) и уходят в таблицу после его обновления. **Закупка за неделю одним текстом**: даты в тексте (`zkDateOf`: «29.10», «29 октября», день недели, «вчера», дата в шапке сообщения MAX) задают дату блока; повтор точки — отдельный блок (`ключ#2`, `ключ@мм-дд`). Если точка встречается несколько раз, `zkPlan` подбирает каждой свою дату накладных по совпадению товаров и количества (`zkScore`), блоки с одной и той же накладной объединяются (`zkAll`, «Разделить» → `apart`).
- **Товары, Поставщики** (реквизиты, печать и подпись, ID ЭДО), **Данные, Прибыль, События, Задачи** (мои личные).
- Работа **без связи**: всё сохраняется на устройстве, неотправленные правки переживают перезагрузку и уходят в таблицу, когда связь появится. Документ, который есть на устройстве, но не дошёл до таблицы, отправляется заново. Ошибки связи показывают настоящую причину.

## 3. Как устроен код (для правок)

```
dev/src/app.html      — основной код: разметка + стили + логика (один большой файл, без фреймворков)

dev/src/seed_seg.js   — начальные данные, newDraft, migrate
dev/Code.template.gs  — серверный скрипт Google Таблицы (файл Code.gs в Apps Script). ПАРОЛЕЙ В НЁМ НЕТ
dev/Passwords.template.gs — шаблон файла «Пароли» в Apps Script (только ПАРОЛЬ, настоящие пароли — у Даниила)
dev/build.py          — сборка → dev/out/ (b.js для проверки, tilda-block.html, test.html)
dev/tools/min.js, repo.js — сжатие и выкладка в корень: app.js, index.html (app.js?v=<хеш>), sw.js

dev/test/smoke.py     — открывает все вкладки на ПК и телефоне (Playwright), считает ошибки
```

Ключевые места в `app.html`: `calc()` (расчёт строк, НДС), `commitDoc()` (сохранение документа), `flush()/buildChanges()` (отправка правок в таблицу), `pull()/applyServer()` (загрузка), `renderDoc/renderLines` (форма документа), `ps*` (поиск товара), `renderCalendar/drawDayTasks/dtRow/dtEdRow` (календарь и задачи), `docTasks()` (автозадачи), `dvPoints/renderDriver` (маршрут), `renderJournal/jRowHtml/onJClick` (журнал), `showPreview/showPreviewSet` (просмотр и печать), `cardEditor/renderCustomers` (карточки), `pl*` (мой прайс), `imp*`/`mul*` (заказ из файла), `phAdd` (фото), `START_TAB` (стартовая вкладка).

Листы таблицы задаёт объект `S` в Code.gs: Поставщики, Заказчики, Товары, Цены, СТЕ, Контракты, Журнал, События, Задачи на день, Фото задач, Настройки пользователей, Закупочные цены, Себестоимость накладных, Налоги для прибыли, Закупки.

## 4. Как выполнять задачу (порядок работы)

1. **План.** Перед правками напиши короткий план на русском: что поменяешь и как Даниил это увидит на сайте. Если задача неясна или затрагивает деньги, номера документов, госконтракты — задай вопрос.
2. **Правки точечные**: меняй нужные куски в `dev/src/*` и `dev/Code.template.gs`, не переписывай файлы целиком, не меняй то, о чём не просили.
3. **Сборка и проверка** (обязательно перед PR):
   ```
   cd dev && python3 build.py && node --check out/b.js
   node test/server.js > /tmp/mock.log 2>&1 &     # тестовый сервер :8787, пароли 1111/2222/3333/4444 (Даниил/Наталья/Гриша/Склад)
   python3 test/smoke.py                         # обе строки должны быть «ошибок: 0»
   ```
   - Для новой функции напиши свой короткий сценарий на Playwright (по образцу `dev/test/smoke.py`): войти нужным пользователем, сделать действие, проверить результат на странице и в данных (`curl localhost:8787/dump` — содержимое «таблицы»).
   - Проверяй на ширине телефона 360–412 px: `document.documentElement.scrollWidth` должен быть равен ширине экрана.
   - Библиотеки с cdnjs (xlsx, html2canvas, jspdf) в тестах подменяй локальными: `npm pack xlsx@0.18.5 html2canvas@1.4.1 jspdf@2.5.1` и `page.route('**/xlsx.full.min.js', …)`.
   - Тестовый сервер останавливай по номеру процесса (`kill <PID>`), **не** командой `pkill -f` с тем же текстом в команде — она убьёт саму себя.
4. **Выкладка в корень** (сайт грузит `app.js` из корня репозитория):
   ```
   cd dev/tools && npm ci && node min.js ../out/tilda-block.html ../out/min.html && node repo.js ../out/min.html
   ```
   Закоммить вместе: изменённые `dev/src/*`, `dev/Code.template.gs` (если менялся) **и** пересобранные `app.js`, `index.html` в корне. Папку `dev/out/` не коммить.
5. **PR.** Описание PR на русском, по шаблону:
   - **Что сделано** — 2–5 пунктов, как это выглядит на сайте;
   - **Как проверено** — какие тесты/сценарии прошли;
   - **Что сделать Даниилу** — по шагам. Всегда: «Нажмите на GitHub зелёную кнопку Merge pull request → Confirm merge. Через 1–2 минуты обновите сайт, на телефоне закройте и откройте приложение». Если менялся Code.gs — добавь шаги из раздела 5.
   - **На что обратить внимание** — подводные камни, особенно по госконтрактам и налогам.

## 5. Code.gs (Google Apps Script) — как Даниил его обновляет

- В Apps Script таблицы «Документы ФД» два файла: **Code.gs** (код, = `dev/Code.template.gs`) и **Пароли.gs** (пароли, = `dev/Passwords.template.gs` с настоящими паролями).
- **Никогда не добавляй пароли и блок `USERS` в `dev/Code.template.gs`** и вообще в репозиторий — он открыт всем. Новые пользователи/роли — только как инструкция Даниилу, что вписать в «Пароли.gs».
- Новое поле в карточках сохраняется в таблицу, только если добавлена колонка в `S` в Code.gs. Добавляй колонки **в конец** списка, ничего не переставляй.
- Сайт должен работать и со старым Code.gs (Даниил может вставить его позже): новые действия сервера — с понятной ошибкой на сайте, если их ещё нет.
- Шаги для Даниила (вставляй в PR, если Code.gs менялся):
  1. Открыть в GitHub файл `dev/Code.template.gs` → кнопка «Copy raw file» (значок двух квадратиков).
  2. Таблица «Документы ФД» → «Расширения» → «Apps Script» → файл **Code.gs** → выделить всё (Ctrl+A) → вставить (Ctrl+V) → «Сохранить». Файл «Пароли.gs» **не трогать**.
  3. «Развернуть» → «Управление развёртываниями» → карандаш → «Новая версия» → «Развернуть».
  4. Если код стал использовать новые сервисы Google — сначала выбрать функцию `authorize` → «Выполнить» → «Разрешить».

## 6. Чего не делать

- Не храни в репозитории пароли, печати/подписи, данные заказчиков из таблицы, заявки и документы (репозиторий публичный).
- Не меняй нумерацию документов, расчёт сумм и НДС, печатные формы ТОРГ‑12/УПД без прямой просьбы — это бухгалтерские документы.
- Не удаляй данные и колонки таблицы. Не меняй адрес веб-приложения (API_URL) в `app.html`.
- Файлы заказов для заказчиков (Excel по шаблону «Заказ для сайта») в этом репозитории не делай — это делается в обычном чате.
